ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) на разработку VK-бота «J2J_Bot» (Python-версия) для сообщества «Java старт | Jump2Java»
1. Общие сведения
•	Название бота: J2J_Bot
•	Платформа: ВКонтакте (личные сообщения и групповой чат)
•	Цель:
o	Отвечать на теоретические вопросы по Java, используя загруженные учебники (русские и английские).
o	Выполнять и проверять Java-код с мгновенной выдачей правильного решения при ошибке (режим «страховка»).
•	Принцип: учебный ассистент, не экзаменатор. Тестирование знаний не входит в MVP.
•	Объём MVP: базовая помощь без учёта прогресса студентов (аналитика – версия 2.0).
2. Функциональные требования
2.1. Ответы на теоретические вопросы (RAG)
1.	Студент задаёт вопрос на русском или английском языке.
2.	Бот выполняет многоязычный векторный поиск:
o	Преобразует запрос в вектор с помощью эмбеддинг-модели (например, intfloat/multilingual-e5-small или paraphrase-multilingual-MiniLM-L12-v2).
o	Ищет в ChromaDB (векторная БД) 3–5 наиболее релевантных фрагментов из учебников.
3.	Передаёт найденные фрагменты + вопрос в DeepSeek API с инструкцией:
«Ответь на русском языке строго по предоставленным фрагментам. Если ответа нет – скажи об этом. Не используй свои знания. Укажи источник: название книги, автор, главу».
4.	DeepSeek генерирует ответ. Температура = 0.1–0.3.
5.	Если ответ не найден – бот отправляет: «Я не могу найти точный ответ… Попробуйте переформулировать» + robot_sad.png.
6.	Визуальное сопровождение:
o	Сначала отправляется robot_thinking.png с текстом «Секунду, думаю… 🤔».
o	Через 1–3 секунды – основной ответ с robot_happy.png (успех) или robot_sad.png (неудача).
2.2. Выполнение и проверка Java-кода (режим «страховка»)
2.2.1. Механизм выполнения
•	Бот распознаёт код по команде /run или по тройным бэктикам java ....
•	Код отправляется в JDoodle API (Java 17).
•	Лимиты: бесплатный тариф – 20 запросов в сутки.
o	Счётчик хранится в SQLite, сброс в 00:00 UTC.
o	При достижении лимита – сообщение: «⚠️ Дневной лимит проверки кода (20 запросов) исчерпан».
o	Администратор может посмотреть статус (/jdoodle_status) и сбросить лимит (/reset_jdoodle_limit).
o	Переменная JDODDLE_PLAN=free (или pro – лимит отключается).
2.2.2. Страховка
•	Успешное выполнение → robot_happy.png + вывод программы.
•	Ошибка → robot_sad.png + сообщение об ошибке + немедленно эталонный код и объяснение.
•	Эталон генерируется через DeepSeek (или берётся из заготовок, если задание распознано).
•	Команда /explain выдаёт правильное решение без предварительной отправки кода.
•	Бот не требует повторных попыток – даёт решение сразу при первой ошибке.
2.3. Вспомогательные команды
•	/start, /help – приветствие с robot_greeting.png и текстом:
*«Привет! Я Java-робот 🤖. Помогаю студентам JUMP2JAVA с теорией и кодом.»*
•	/about – информация о боте, версия.
•	/explain – эталонное решение.
Визуальная задержка: на любую обрабатываемую команду / вопрос сначала отправляется robot_thinking.png, затем через 1–3 сек – итоговый ответ.
2.4. Визуальный персонаж (статический робот)
Изображение	Событие	Текст
robot_greeting.png	/start или первое обращение	«Привет! Я Java-робот 🤖. Помогаю студентам… Спроси меня о Java или отправь код на проверку»
robot_thinking.png	Начало обработки	«Секунду, думаю… 🤔»
robot_happy.png	Успешный ответ / выполнение кода	«✅ Код выполнен без ошибок. Молодец!» (или текст ответа)
robot_sad.png	Ошибка / ответ не найден	«Ой, что-то пошло не так 😕» + пояснение / эталон
Изображения хранятся в папке static проекта (на BotHost). При старте бот загружает их в VK через API и использует полученные attachment-строки.
2.5. Административные команды
Доступны только пользователю с VK ID из переменной ADMIN_IDS.
Команда /admin в ЛС → инлайн-клавиатура:
text
[🔄 Переиндексировать всё] [🗑 Очистить базу]
[📂 Показать файлы]       [❌ Удалить файл/папку]
[ℹ️ Статус библиотеки]    [JDoodle: статус] [JDoodle: сброс лимита]
Команды управления библиотекой:
•	/reload_knowledge – переиндексация книг из папки Литература.
•	/clear_knowledge – удаление всех чанков из ChromaDB.
•	/list_files [путь] – просмотр файлов.
•	/delete_file / /delete_folder – удаление (без возможности удалить корневую Литература).
•	/status – количество книг, чанков, дата последней индексации.
Команды JDoodle:
•	/jdoodle_status – остаток запросов.
•	/reset_jdoodle_limit – сброс счётчика.
3. Архитектура и стек технологий (Python)
3.1. Платформы и инструменты
•	Разработка: Replit (Python 3.10+) или локально.
•	Хостинг: BotHost (тариф «ПРО» или «Basic»), обязательно включить общее хранилище (shared storage).
•	Язык: Python 3.10+ (asyncio).
•	Фреймворк для VK: vkbottle (асинхронный, Long Poll API).
•	Система контроля версий: GitHub.
3.2. Базы данных
•	Векторная БД: ChromaDB (сохраняется на диск, например, в /app/shared/chroma_db).
•	Реляционная БД: SQLite (файл j2j_bot.db – можно хранить в общем хранилище или локально).
3.3. Интеграции и библиотеки
•	VK API: vkbottle (Long Poll, отправка сообщений, клавиатуры, загрузка фото).
•	LLM: DeepSeek API (requests или aiohttp).
•	Эмбеддинги: sentence-transformers с многоязычной моделью (например, intfloat/multilingual-e5-small).
•	Извлечение текста из PDF: pypdf или pdfplumber.
•	RAG-пайплайн: langchain + chromadb.
•	Выполнение кода: requests к JDoodle API.
•	Работа с SQLite: aiosqlite или sqlite3 + asyncio.to_thread.
•	Переменные окружения: os.environ + python-dotenv (для локальной разработки).
3.4. Процесс инициализации базы знаний
•	Корневая папка с литературой: /app/shared/Литература (BotHost, общее хранилище).
•	При команде /reload_knowledge (или при первом запуске):
1.	Рекурсивно сканируется Литература (поддерживаются подпапки: Java Core, Инструменты и т.д.).
2.	Из каждого PDF извлекается текст (pypdf).
3.	Текст разбивается на чанки (~500 токенов, перекрытие 50 символов).
4.	Для каждого чанка вычисляется эмбеддинг (многоязычная модель).
5.	Чанки + эмбеддинги + метаданные (название книги, автор, глава, страница) сохраняются в ChromaDB.
6.	Результат (количество книг / чанков) отправляется администратору в ЛС и логируется.
3.5. Безопасность и лимиты JDoodle
•	Выполнение кода только через JDoodle API.
•	Счётчик запросов хранится в SQLite.
•	При недоступности JDoodle – сообщение: «Сервис выполнения временно недоступен, попробуйте позже».
4. Этапы разработки (MVP)
1.	Настройка окружения – получение токенов VK, DeepSeek, JDoodle, настройка BotHost.
2.	Базовый эхо-бот на vkbottle (Long Poll).
3.	Интеграция DeepSeek API (без RAG, как временное решение).
4.	Интеграция JDoodle API – выполнение кода, счётчик лимитов, команды /jdoodle_status, /reset_jdoodle_limit.
5.	Добавление статического персонажа – загрузка PNG в VK, отправка эмоций с задержкой.
6.	Настройка RAG (база знаний) – индексация PDF, ChromaDB, векторный поиск, ответы только по учебникам.
7.	Режим страховки – немедленная выдача эталона при ошибке, команда /explain.
8.	Административные команды для библиотеки – /reload_knowledge, /clear_knowledge, /list_files, /delete_file, /delete_folder, /status.
9.	Тестирование в группе VK – проверка всех сценариев.
5. Критерии приемки (MVP)
•	Бот отвечает на вопросы, используя только загруженные учебники (проверяется вопросом, ответ на который есть в книгах, но DeepSeek без контекста не знает).
•	При отсутствии ответа – фраза «Я не могу найти точный ответ…» + robot_sad.png.
•	Java-код выполняется через JDoodle. Успех → robot_happy.png + вывод.
•	Ошибка → robot_sad.png + немедленно эталон + объяснение.
•	/explain выдаёт эталон без отправки кода.
•	Лимит 20 запросов JDoodle работает, администратор может сбросить.
•	Администратор через /admin управляет библиотекой и JDoodle.
•	Визуальные эмоции и задержка robot_thinking.png соблюдены.
•	Время ответа (RAG) ≤ 10 секунд.
•	Нет модуля тестирования / прогресса студентов (будет в 2.0).
6. Документация и развёртывание на BotHost
6.1. Переменные окружения
Переменная	Описание
VK_TOKEN	токен сообщества VK
DEEPSEEK_API_KEY	ключ DeepSeek API
JDODDLE_CLIENT_ID	Client ID JDoodle
JDODDLE_CLIENT_SECRET	Client Secret JDoodle
JDODDLE_PLAN	free или pro
ADMIN_IDS	VK ID администратора (один)
KNOWLEDGE_ROOT	по умолчанию /app/shared/Литература
SHARED_DIR	задаётся BotHost автоматически
6.2. Инструкция по развёртыванию
1.	Создать Python-проект на BotHost (из GitHub).
2.	Включить «Общее хранилище» (shared storage).
3.	Загрузить папку Литература через раздел «Общие файлы» (ZIP-архивом, распаковать в /app/shared/Литература).
4.	В настройках бота добавить переменные окружения (см. выше).
5.	Выполнить редеплой.
6.	Написать боту /reload_knowledge для индексации книг.
7.	Проверить команды /run и /explain.
6.3. Команды для студентов
•	/start, /help – приветствие.
•	/run (с кодом) – выполнить Java-код (при ошибке – эталон).
•	/explain – правильное решение.
•	/about – информация о боте.
