Задача: Разработать VK-бота J2J_Bot на Python (первая фаза) согласно приложенному техническому заданию (адаптированному под Python и BotHost). Реализовать только функционал, связанный с ответами на теоретические вопросы по Java (RAG, управление библиотекой, визуальный персонаж, административные команды для работы с книгами). Всё, что относится к выполнению и проверке Java-кода (JDoodle, команды /run, /explain) — исключить. Бот должен быть готов к развёртыванию на BotHost с использованием общего хранилища для папки Литература.

1. Общие требования
Язык: Python 3.10+ (асинхронный).

Фреймворк для VK: vkbottle (Long Poll API).

RAG-пайплайн:

Извлечение текста из PDF: pypdf или pdfplumber.

Векторная БД: chromadb (сохраняется на диск, путь /app/shared/chroma_db или ./chroma_db).

Эмбеддинг-модель: sentence-transformers с многоязычной моделью (например, intfloat/multilingual-e5-small или paraphrase-multilingual-MiniLM-L12-v2).

Генерация ответов: DeepSeek API (через requests или aiohttp).

База данных для служебной информации: SQLite (файл j2j_bot.db, хранить в общем хранилище или в рабочей папке). Хранить: дату последней индексации, количество книг/чанков, логи операций (опционально).

Административные команды:

/reload_knowledge (переиндексация всех книг из папки Литература),

/clear_knowledge (очистка ChromaDB),

/status (статус библиотеки: количество книг, чанков, дата последней индексации),

/list_files [путь], /delete_file, /delete_folder (работа с файлами в папке Литература, с защитой от удаления корневой папки).

Команда /admin в ЛС открывает клавиатуру (inline или обычную) с кнопками для этих действий.

Персонаж (статический робот):

Четыре PNG-файла: robot_greeting.png, robot_thinking.png, robot_happy.png, robot_sad.png.

При старте бот загружает эти файлы в VK (методы photos.getMessagesUploadServer, photos.saveMessagesPhoto) и сохраняет attachment-строки в памяти/файле, чтобы использовать при отправке сообщений.

При обработке любого запроса (вопрос, команда) сначала отправляется robot_thinking.png + текст «Секунду, думаю… 🤔», затем через 1–3 секунды – ответ с соответствующей эмоцией (robot_happy.png или robot_sad.png).

Команды для студентов:

/start, /help – приветствие с robot_greeting.png и текстом: *«Привет! Я Java-робот 🤖. Помогаю студентам JUMP2JAVA с теорией. Спроси меня о Java — я отвечу на основе учебников. (Проверка кода появится позже)»*

/about – информация о боте, версия (1.0 – теория).

Обработка обычных текстовых сообщений (вопросов):

Выполняется векторный поиск в ChromaDB (3–5 чанков).

Формируется запрос к DeepSeek API с инструкцией отвечать строго по фрагментам, с указанием источников.

Ответ отправляется пользователю. Если фрагментов нет или DeepSeek не может ответить – отправляется заготовленное сообщение об отсутствии ответа.

2. Интеграция с BotHost (общее хранилище)
Папка с литературой должна находиться по пути, указанному в переменной окружения KNOWLEDGE_ROOT (по умолчанию /app/shared/Литература).

Использовать переменную SHARED_DIR (предоставляется BotHost) или /app/shared как корень общего хранилища.

В коде предусмотреть, что если KNOWLEDGE_ROOT не задан, то используется os.environ.get('SHARED_DIR', '/app/shared') + '/Литература'.

При индексации (/reload_knowledge) бот должен рекурсивно обойти все подпапки внутри Литература (Java Core, Инструменты, Фреймворки, Веб-технологии, Подготовка к собеседованию и любые другие).

ChromaDB и SQLite рекомендуется хранить в постоянной директории (например, /app/shared/chroma_db и /app/shared/bot_data), чтобы данные не терялись при перезапуске контейнера.

3. Требования к коду и структуре проекта
Создать в корне проекта папку static, внутри – четыре пустых или минимальных PNG-файла-заглушки с указанными именами (пользователь заменит их позже).

Реализовать асинхронную загрузку картинок в VK при старте бота (с обработкой ошибок, повторными попытками).

Для работы с VK API использовать vkbottle (удобно для Long Poll, отправки сообщений, клавиатур, загрузки фото).

Логирование: выводить в консоль (stdout) информацию о запуске, индексации, ошибках.

Все секреты (токены) должны читаться из переменных окружения: VK_TOKEN, DEEPSEEK_API_KEY, ADMIN_IDS (один ID, как строка).

Предусмотреть, что для административных команд проверка прав происходит по ADMIN_IDS.

Команды /run и /explain не реализовывать; при их получении бот должен отвечать: «Функция проверки кода будет добавлена в следующей версии. Пока я могу отвечать только на теоретические вопросы по Java.»

4. Обработка ошибок
Если при индексации какой-то PDF не читается – пропустить его, записать ошибку в лог, продолжить индексацию остальных.

Если DeepSeek API недоступен – отвечать: «Сервис ответов временно недоступен, попробуйте позже» + robot_sad.png.

Если векторная БД пуста (ни одной книги не проиндексировано) – на любой теоретический вопрос отвечать: «База знаний ещё не загружена. Администратор должен выполнить /reload_knowledge».

5. Дополнительные требования к реализации
Использовать asyncio и асинхронные методы vkbottle.

Для вызова DeepSeek API и JDoodle (в будущем) использовать aiohttp (или httpx) для неблокирующих запросов.

Для работы с SQLite – aiosqlite или sqlite3 с asyncio.to_thread.

Индексация должна быть достаточно эффективной: при повторном /reload_knowledge старые чанки из Chroma удаляются (или коллекция пересоздаётся).

Метаданные чанков должны включать: book_title (имя файла или извлечённое название), author (если удаётся получить), chapter (если есть), page (если есть).

При ответе на вопрос обязательно указывать источник(и) (название книги, автора, главу), как это вернёт DeepSeek.

6. Критерии завершения фазы 1
Бот успешно запускается в Replit (или локально), подключается к VK через Long Poll.

Команда /start отправляет robot_greeting.png с правильным текстом.

Администратор (по VK ID) может выполнить /reload_knowledge – бот индексирует PDF из папки /app/shared/Литература (или тестовой локальной папки).

После индексации бот отвечает на вопросы по содержанию книг, ссылаясь на источники.

Вопрос, ответа на который нет в книгах, приводит к сообщению «Я не могу найти точный ответ…» + robot_sad.png.

При обработке любого запроса появляется robot_thinking.png с задержкой 1–3 секунды.

Команда /admin в ЛС открывает клавиатуру, кнопки которой выполняют соответствующие действия.

Команды /run и /explain возвращают заглушку.

Код загружен на GitHub (в репозиторий пользователя).

7. Финальное сообщение для пользователя
После успешного создания и настройки бота вывести в консоль (и в ответе пользователю):

text
✅ Фаза 1 бота J2J_Bot (Python) завершена.
   - Реализованы: RAG (ChromaDB + эмбеддинги + DeepSeek), управление библиотекой, визуальный персонаж.

   - Для развёртывания на BotHost:

   - Замените файлы в static/ на реальные PNG-изображения робота.
Важно для агента:
Если реализация многоязычной эмбеддинг-модели через sentence-transformers требует больших ресурсов (модель весит ~1 ГБ), можно использовать более лёгкую альтернативу: all-MiniLM-L6-v2 (английский) + предварительный перевод запросов на английский, но это отступление от ТЗ. Рекомендуется всё же использовать многоязычную модель. При невозможности – сделать заглушку с поиском по ключевым словам, но явно указать, что это временное решение.
