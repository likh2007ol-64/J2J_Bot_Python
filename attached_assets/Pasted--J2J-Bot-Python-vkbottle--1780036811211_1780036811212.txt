Контекст: Бот J2J_Bot (Python, vkbottle) прошёл автоматическое тестирование, но при ручном тестировании в VK выявлены проблемы:

Административные команды (/reload_knowledge, /status, /admin, /jdoodle_status, /reset_jdoodle_limit) не распознаются — бот отвечает «Неизвестная команда. Напишите /help для справки».

Кнопки в интерфейсе /admin (например, «Статус библиотеки») тоже не работают.

Блок Java-кода в тройных бэктиках (без команды /run) воспринимается как текстовый вопрос, а не как запрос на выполнение.

Задача: Исправить эти ошибки, чтобы бот корректно реагировал на:

Административные команды (только для пользователя с VK ID из ADMIN_IDS):

/reload_knowledge — переиндексация книг.

/status — статус библиотеки.

/admin — показать клавиатуру с кнопками.

/jdoodle_status — остаток лимитов JDoodle.

/reset_jdoodle_limit — сброс счётчика.

Автоматическое распознавание Java-кода в сообщениях, содержащих блок java ... (без команды /run). Такой код должен отправляться на выполнение в JDoodle, а не обрабатываться как вопрос к RAG.

Шаги для исправления:
Проверить ADMIN_IDS:

Убедиться, что переменная окружения ADMIN_IDS содержит правильный числовой VK ID администратора (тот, который отправляет команды).

В коде обработчиков команд проверить, что проверка прав происходит корректно (например, event.object.message.peer_id или event.object.message.from_id сравнивается с ADMIN_IDS).

Добавить/исправить обработчики команд в handlers.py (или в admin.py, если он есть):

Для каждой из перечисленных команд создать декоратор @bot.on.message(text="/reload_knowledge") (или использовать vkbottle правила).

Обеспечить, чтобы команды работали только в личных сообщениях (peer_id = from_id) и только для администратора.

Команда /admin должна отправлять клавиатуру (inline или обычную) с кнопками, которые вызывают соответствующие действия (например, через callback или текстовые команды).

Проверить работу кнопок в /admin:

При нажатии на кнопку «Статус библиотеки» бот должен вызывать ту же логику, что и /status.

Убедиться, что callback-обработчики или обработчики текстовых сообщений для кнопок зарегистрированы.

Исправить распознавание Java-кода:

В обработчике текстовых сообщений (который сейчас идёт в RAG) добавить проверку: если сообщение содержит блок кода с языком java (регулярное выражение для java ...), то не отправлять в RAG, а передать в функцию выполнения JDoodle (как если бы была команда /run).

Также можно поддерживать блоки без указания языка, но с явным Java-синтаксисом (по желанию).

Важно: при этом должны соблюдаться те же визуальные эмоции (robot_thinking.png, затем результат).

Проверить, что после исправлений:

Администратор может выполнить /reload_knowledge и получить отчёт.

/status показывает количество книг/чанков.

/admin открывает панель, и кнопки работают.

Блок кода java ... (без /run) выполняется и возвращает результат или ошибку с эталоном.

Обычные текстовые вопросы (не содержащие код) по-прежнему идут в RAG.

Ожидаемый результат:
После исправлений бот должен пройти ручное тестирование по таблице:

Пункты 4,5,6,8,9 должны работать корректно (возвращать нужные ответы, а не «Неизвестная команда»).

Пункт 7 (код без /run) должен выполняться и выводить результат или ошибку с эталоном.
