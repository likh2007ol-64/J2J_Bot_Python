Контекст: У меня есть работающий VK-бот на Python (vkbottle), первая фаза (RAG по учебникам, загрузка изображений, админка для библиотеки) уже реализована. Все необходимые API-ключи получены и оплачены:

DEEPSEEK_API_KEY – баланс положительный, можно использовать.

JDODDLE_CLIENT_ID, JDODDLE_CLIENT_SECRET – получены.

JDODDLE_PLAN = free (бесплатный тариф, лимит 20 запросов/сутки).

Задача: Добавить вторую фазу – выполнение и проверку Java-кода через JDoodle API с режимом «страховка» (немедленная выдача эталонного решения и объяснения при ошибке). Использовать DeepSeek для генерации эталонов (он оплачен). В коде бота предусмотреть, что если переменные окружения для JDoodle отсутствуют, выводить понятное предупреждение и отключать соответствующие команды.

1. Интеграция JDoodle API
Реализовать функцию execute_java_code(code: str) -> dict, которая отправляет код в JDoodle (Java 17) и возвращает {'output': str, 'error': bool, 'message': str}.

Использовать переменные окружения:
JDODDLE_CLIENT_ID, JDODDLE_CLIENT_SECRET, JDODDLE_PLAN (по умолчанию free).

Лимиты (только для free):

Хранить счётчик запросов за сегодня в SQLite (таблица jdoodle_limits с полями date, count).

При достижении 20 – не отправлять код в JDoodle, а возвращать сообщение о лимите.

Сброс счётчика в 00:00 UTC.

Если JDODDLE_PLAN = pro – лимит не проверять.

2. Распознавание кода в сообщениях пользователя
Команда /run – всё, что идёт после команды в том же сообщении, считается кодом. Можно также поддерживать многострочный ввод.

Блок кода в тройных бэктиках с указанием java (например, java ...).

Если код не обнаружен – ответить: «Пожалуйста, отправьте код на Java после команды /run или в тройных бэктиках`.

3. Основная логика (с визуальными эмоциями)
При получении кода:

Отправить robot_thinking.png + «Секунду, думаю… 🤔».
Проверить лимит (если free). Если лимит исчерпан – отправить сообщение об этом и robot_sad.png, завершить.
Выполнить код через JDoodle.
Если успех (нет ошибки компиляции/выполнения):
Отправить robot_happy.png + ✅ Код выполнен без ошибок. Молодец! + вывод программы (stdout).
Если ошибка (JDoodle вернул stderr или error=true):
Отправить robot_sad.png + сообщение: «Ошибка: [техническое сообщение от JDoodle]. Ниже — правильное решение с объяснением, чтобы ты мог разобраться».
Немедленно сгенерировать эталонный код и объяснение через DeepSeek API (см. п. 4).
Отправить эталон и объяснение пользователю.
4. Генерация эталонного решения (страховка)
При ошибке в коде (или по команде /explain) бот должен:

Передать в DeepSeek API:
Код студента (тот, который вызвал ошибку, или пустой для /explain? Для /explain – просто запрос на тему «напиши правильное решение задачи X», но чтобы не усложнять, можно всегда запрашивать исправление кода).
Контекст: задание (если удаётся определить из сообщения студента или из истории) – опционально.
Инструкцию: «Ты – помощник по Java. Студент написал код, который содержит ошибку. Исправь код и дай правильное решение с подробным объяснением на русском языке. Ошибка: [сообщение об ошибке]. Код студента: ...».
Получить от DeepSeek исправленный код и объяснение.
Отправить пользователю:
text
📖 Правильное решение:
```java
(исправленный код)
💡 Объяснение: ...
text
Команда /explain (без предварительной отправки кода) – запросить у DeepSeek эталон по указанной студентом задаче (если задача не указана – попросить уточнить).
Можно упростить: /explain без аргументов – выдать «Для какой задачи нужно объяснение? Напишите условие».

5. Административные команды для JDoodle
/jdoodle_status – показать текущее количество использованных запросов за сегодня и лимит (20 или «unlimited» для pro).

/reset_jdoodle_limit – принудительный сброс счётчика (полезно при тестировании).

Эти команды должны быть доступны только пользователю с ADMIN_IDS.

Добавить соответствующие кнопки в интерфейс /admin.

6. Обработка ошибок и логирование
Если JDoodle недоступен (ошибка сети, таймаут) – ответ: «Сервис выполнения временно недоступен, попробуйте позже» + robot_sad.png.

Если DeepSeek недоступен (или ошибка) – при страховке выдать сообщение: «Не удалось сгенерировать эталонное решение. Попробуйте позже. Ошибка: ...» + robot_sad.png.

Логировать все запросы к JDoodle и DeepSeek (в консоль и/или в файл).

Все секреты должны читаться из переменных окружения. При их отсутствии бот должен при запуске выводить предупреждение и отключать соответствующий функционал (например, если нет JDoodle ключей – команды /run и /explain отвечают «модуль проверки кода не настроен»).

7. Интеграция с существующим кодом
Не удалять и не изменять обработчики первой фазы (RAG, /reload_knowledge, /clear_knowledge, /status, /list_files, /delete_file, /delete_folder, админку для библиотеки, загрузку изображений, команды /start, /help, /about).

Добавить новые обработчики для /run, /explain, /jdoodle_status, /reset_jdoodle_limit.

В SQLite создать таблицу jdoodle_limits (если её нет) и, возможно, таблицу для логов (опционально).

Расширить клавиатуру /admin новыми кнопками: «JDoodle: статус», «JDoodle: сброс лимита».

8. Тестирование в Replit
После внесения изменений бот должен корректно обрабатывать:

Успешный Java-код (например, System.out.println("Hello");).

Ошибочный код (например, пропущенная точка с запятой) – должен выдать эталон через DeepSeek.

Команду /explain (попросить ввести задание или выдать эталон по последнему ошибочному коду – на ваше усмотрение, но лучше просто попросить уточнить задание).

Лимит 20 запросов – после 20 успешных или неуспешных вызовов JDoodle бот должен блокировать новые запросы и показывать сообщение.

Команды администратора для JDoodle.

Все визуальные эмоции (thinking, happy, sad) должны отправляться в нужные моменты.
