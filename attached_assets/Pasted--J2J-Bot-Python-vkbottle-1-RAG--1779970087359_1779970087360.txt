Контекст: Бот J2J_Bot (Python, vkbottle) полностью реализован: фаза 1 (RAG по учебникам, административная панель, визуальный персонаж) и фаза 2 (JDoodle, страховка через DeepSeek, лимиты). Все API-ключи добавлены в Secrets Replit, DeepSeek оплачен, книга Core_Java_vol1.pdf загружена в bot/knowledge/ и проиндексирована (1644 чанка). Изображения роботов находятся в static/.

Задача: Провести автоматическое (или с помощью эмуляции) тестирование бота в среде Replit, проверить критически важные сценарии, зафиксировать результаты, при необходимости исправить ошибки в коде.

1. Подготовка к тестированию
Убедиться, что бот запущен и активен (Long Poll VK).

Сбросить счётчик JDoodle (через /reset_jdoodle_limit от имени администратора, если потребуется).

Очистить старые логи, включить подробное логирование (вывод в консоль).

2. Тест-кейсы (обязательные к проверке)
Фаза 1 – Теория (RAG)
Команда /start – должна отправить robot_greeting.png и текст приветствия.

Вопрос по книге (например: «What is polymorphism in Java?» или «Что такое полиморфизм?»):

Сначала должен прийти robot_thinking.png.

Затем – ответ от DeepSeek на русском языке, с указанием источника (книга, страница) и без сообщения об ошибке.

Если ответ отсутствует или приходит заглушка – проверить баланс DeepSeek и правильность запроса.

Вопрос, ответа на который нет в книге (например: «What is the capital of France?»):

Должен вернуться robot_sad.png и сообщение «Я не могу найти точный ответ…» (или «Источник временно не доступен» – но при работающем DeepSeek должно быть именно «не могу найти»).

Административная панель /admin – должна показывать клавиатуру со всеми кнопками (управление библиотекой, JDoodle).

Команда /reload_knowledge (от администратора) – должна переиндексировать книги и вернуть отчёт (количество книг, чанков). После этого повторить вопрос из п.2 – ответ должен остаться корректным.

Фаза 2 – Практика (JDoodle + страховка)
Выполнение корректного Java-кода через /run:

Отправить: /run System.out.println("Hello J2J");

Ожидается: robot_thinking.png → robot_happy.png + вывод Hello J2J.

Выполнение кода с синтаксической ошибкой (например, пропущена точка с запятой):

Отправить: /run System.out.println("Error") (без ;)

Ожидается: robot_thinking.png → robot_sad.png + сообщение об ошибке + эталонное решение (исправленный код) + объяснение на русском языке (сгенерированное DeepSeek).

Выполнение кода, который не содержит public class (голый код) – бот должен автоматически обернуть в класс (это уже реализовано, проверить).

Команда /explain:

Отправить: /explain Напиши метод, который возвращает сумму двух чисел

Ожидается: эталонное решение (код) и объяснение на русском языке.

Лимит JDoodle:

Сделать 21 запрос (можно с пустышками, но лучше с реальным кодом). После 20-го запроса бот должен отвечать: «⚠️ Дневной лимит проверки кода (20 запросов) исчерпан…» и не отправлять код в JDoodle.

Проверить, что администратор может посмотреть статус (/jdoodle_status) и сбросить лимит (/reset_jdoodle_limit).

Автоматическое распознавание кода в тройных бэктиках:

Отправить сообщение с блоком:

java
public class Test { public static void main(String[] args) { System.out.println("OK"); } }
Бот должен выполнить код без команды /run (если такая логика есть). Если нет – проверить, что команда /run с таким блоком тоже работает.

Общее
Визуальные эмоции: убедиться, что robot_thinking.png отправляется перед любым длительным действием, а robot_happy.png/robot_sad.png – после.

Обработка ошибок API:

Симулировать недоступность JDoodle (например, временно отключить сеть или указать неверные ключи) – бот должен ответить: «Сервис выполнения временно недоступен, попробуйте позже» + robot_sad.png.

Симулировать недоступность DeepSeek (например, неверный ключ) – при страховке должно быть сообщение об ошибке генерации эталона.

Права администратора: обычный пользователь (не ADMIN_IDS) не должен иметь доступа к /reload_knowledge, /jdoodle_status, /reset_jdoodle_limit, /clear_knowledge и т.д.

Определить причину (логи, код).

Перезапустить бота и повторить тест.

Зафиксировать изменения в Git (commit).
